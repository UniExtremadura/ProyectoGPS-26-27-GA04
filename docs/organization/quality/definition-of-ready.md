# Definition of Ready (DoR) 
 
Para que una Historia de Usuario (US) del proyecto Centinela sea considerada lista (Ready) para entrar en el *Sprint Backlog*, debe cumplir estrictamente con las siguientes condiciones: 
 
## Identificación y trazabilidad 
- [ ] La historia de usuario tiene un identificador único y estable (`US-XXX`). 
- [ ] La historia de usuario está asociada a una Épica (`EP-XXX`). 
- [ ] La historia de usuario es trazable a al menos un objetivo del producto (Goal) definido en `goals.md`. 
 
## Valor y alcance 
- [ ] El usuario o stakeholder está claramente identificado (ej. personal técnico, personal de almacén). 
- [ ] La capacidad esperada está claramente descrita. 
- [ ] El valor o beneficio esperado es comprensible. 
- [ ] El alcance y los límites relevantes de la historia están suficientemente claros y respetan las exclusiones (EX-01, EX-02) de Corvalen Dynamics. 
 
## Aceptación 
- [ ] Los criterios de aceptación están definidos. 
- [ ] Los criterios de aceptación son observables y verificables. 
- [ ] Los criterios de aceptación describen el comportamiento esperado sin prescribir innecesariamente la implementación técnica. 
 
## Planificación 
- [ ] Se le ha asignado una prioridad utilizando la técnica MoSCoW. 
- [ ] Se dispone de una estimación de esfuerzo consensuada (en `h-p`). 
- [ ] Se ha identificado el grado de incertidumbre (Bajo / Medio / Alto). 
- [ ] Se conocen y están documentadas las dependencias relevantes y los predecesores técnicos o funcionales. 
 
## Restricciones 
- [ ] Se han identificado los requisitos no funcionales (NFRs) aplicables (ej. accesibilidad, tiempos de respuesta). 
- [ ] Se conocen las restricciones técnicas, organizativas o de proyecto (prohibición de datos militares reales). 
 
## Problemas abiertos 
- [ ] No existen dudas sin resolver que impidan al equipo entender o planificar la historia de usuario. 
- [ ] Cualquier supuesto importante o problema no bloqueante está documentado explícitamente en la especificación.
