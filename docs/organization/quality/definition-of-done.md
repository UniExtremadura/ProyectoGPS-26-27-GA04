# Definition of Done (DoD) 
 
Una Historia de Usuario (US) del proyecto Centinela se considera "Terminada" (Done) cuando satisface todas las condiciones aplicables que se detallan a continuación: 
 
## Implementación 
- [ ] La funcionalidad descrita por la Historia de Usuario ha sido implementada. 
- [ ] La implementación sigue la arquitectura del proyecto y los estándares de código acordados por el Tech Lead. 
- [ ] No queda ningún problema crítico de implementación sin resolver. 
 
## Criterios de Aceptación 
- [ ] Todos los criterios de aceptación asociados con la Historia de Usuario han sido verificados. 
- [ ] Se dispone de evidencia de dicha verificación cuando es requerida. 
- [ ] El comportamiento implementado en el sistema coincide exactamente con la Historia de Usuario aprobada. 
 
## Pruebas (Testing) 
- [ ] Se han ejecutado las pruebas relevantes (automatizadas o manuales). 
- [ ] Las pruebas cubren tanto el comportamiento esperado como las condiciones de error relevantes. 
- [ ] Las pruebas existentes en el resto del sistema continúan pasando correctamente (no se ha roto nada previo). 
 
## Integración 
- [ ] La implementación ha sido integrada en la rama del proyecto acordada (ej. rama `main` o de integración). 
- [ ] La versión integrada compila y/o se ejecuta correctamente. 
- [ ] El cambio no introduce regresiones críticas conocidas en el producto. 
 
## Requisitos No Funcionales (NFRs) 
- [ ] Se han comprobado los requisitos no funcionales aplicables a esta historia. 
- [ ] Se han considerado y respetado las restricciones de seguridad, usabilidad y accesibilidad (datos ficticios, contraste, navegación), tal como dicta la constitución del proyecto. 
 
## Documentación y Trazabilidad 
- [ ] La documentación técnica o de usuario relevante ha sido actualizada si era necesario. 
- [ ] La Historia de Usuario mantiene la trazabilidad hacia su implementación y hacia las evidencias de verificación. 
- [ ] Las decisiones técnicas relevantes o las desviaciones respecto al plan inicial han sido documentadas en la Wiki. 
 
## Revisión (Review) 
- [ ] El código y el trabajo han sido revisados según el proceso acordado por el equipo (ej. revisión de PR aprobada por al menos 1 miembro). 
- [ ] No queda ningún problema bloqueante abierto ni sin resolver.
